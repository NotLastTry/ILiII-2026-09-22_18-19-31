# Практические занятия №7 и №8 — игровой инвентарь и хаотичный ИИ

Проект: Unity 6000.5.9f1, URP, Input System (Both).
Демо-сцена: `Assets/Scenes/Lab7_8_Demo.unity` (копия рабочей `SampleScene` + новые объекты).

---

## 1. Быстрый старт

1. Открыть проект в Unity 6000.5.9f1.
2. Открыть сцену `Assets/Scenes/Lab7_8_Demo.unity`.
3. Нажать **Play**.

Если сцена потерялась или её нужно пересобрать: меню **Lab 7-8 → 1. Создать демо-сцену**.

### Управление

| Клавиша | Действие |
|---|---|
| `WASD` | движение |
| `Shift`-мышь | камера |
| `Tab` | открыть / закрыть инвентарь |
| `ЛКМ` + перетаскивание | перемещение предмета между слотами |
| Перетаскивание на слот экипировки | надеть предмет |
| Двойной клик | надеть / снять предмет |
| `G` (или `Delete`) | выбросить выделенный предмет в мир |
| `E` | подобрать предмет / поговорить с NPC |
| `F` | сдать / отменить квест |
| `ESC` | закрыть инвентарь (вне инвентаря — выход) |

## 2. Практическое занятие №7 — инвентарь

### 2.1. Реализованные механики

| Требование | Где реализовано |
|---|---|
| 1. Перемещение предметов в инвентаре | `InventoryModel.Move`, drag & drop в `InventorySlotUI` / `InventoryUI` |
| 2. Экипировка предмета | `InventoryModel.Equip` / `EquipTo`, слоты `EquipmentSlotUI` |
| 3. Выбрасывание предмета | `InventoryModel.Take` / `TakeEquipped` + `PlayerInventory.DropSlot` + `WorldItemSpawner` |
| 4. Подбор предмета | `ItemPickup` + `PlayerInteractor` + `PlayerInventory.TryPickUp` |
| Доп. задание: изменение характеристик | `CharacterStats` + `StatCalculator` + `PlayerSpeedLink` |

### 2.2. Архитектура

```
Items/
  ItemDefinition.cs   — описание предмета (ScriptableObject): слот, стаки, вес, бонусы
  ItemStack.cs        — стопка в слоте (предмет + количество)
  StatBlock.cs        — набор характеристик, StatType, StatModifier
  StatCalculator.cs   — формула пересчёта характеристик с учётом экипировки
Inventory/
  InventoryModel.cs   — чистая логика: слоты, экипировка, перемещение, добавление, изъятие
  CharacterStats.cs   — MonoBehaviour: базовая статистика + бонусы, события изменений
  PlayerSpeedLink.cs  — переносит итоговую скорость персонажа в PhysicsModule.maxSpeed
Interaction/
  IInteractable.cs, InteractableRegistry.cs, PlayerInteractor.cs, ItemPickup.cs
  WorldItemSpawner.cs — создание предмета в мире (по префабу или процедурно)
UI/
  UIFactory.cs        — построение uGUI из кода (скруглённые панели, текст, иконки)
  SlotViewBase.cs, InventorySlotUI.cs, EquipmentSlotUI.cs
  InventoryUI.cs      — экран инвентаря: сетка, экипировка, характеристики, тултип
  LabHUD.cs           — Canvas, подсказки, всплывающие сообщения, статус ИИ
PlayerInventory.cs    — «владелец» модели на игроке, связывает мир и UI
```

`InventoryModel` не знает про Unity-сцену: это обычный C#-класс, поэтому его
поведение полностью покрыто юнит-тестами (см. раздел 4).

### 2.3. Модель инвентаря

* 24 слота сетки + 8 слотов экипировки (`Head`, `Chest`, `Hands`, `Feet`, `Weapon`, `Shield`, `Amulet`).
* События: `Changed`, `ItemAdded`, `ItemRemoved`, `ItemEquipped`, `ItemUnequipped`
  — на них подписаны UI и `CharacterStats`, поэтому интерфейс и цифры обновляются сами.
* `Move(from, to)`:
  * пустой слот → перенос;
  * тот же предмет и есть место → объединение стопок;
  * другой предмет → обмен местами.
* `Equip(index)`: предмет уходит в свой слот, ранее надетый возвращается в освободившийся
  слот (или в первый свободный, если стопка была не единичной).
* `Unequip(slot)`: снятие возможно только если в инвентаре есть место — предмет не теряется.
* `TryPickUp` атомарен: если предмет не помещается целиком, он остаётся лежать в мире.

### 2.4. Изменение характеристик при экипировке (доп. задание)

Формула (`StatCalculator`):

```
итог = (база + Σ flat) × (1 + Σ percent)
```

* Проценты складываются, а не перемножаются — так результат предсказуем.
* Значения защищены от «отрицательных» результатов (HP ≥ 1, скорость ≥ 0.1).
* `CharacterStats` пересчитывает всё по событию `InventoryModel.Changed`,
  поднимает `Changed` и `GameEventBus.PlayerHealthChanged`.
* `PlayerSpeedLink` переносит `TotalStats.moveSpeed` в `PhysicsModule.maxSpeed`,
  поэтому сапоги скорости реально ускоряют персонажа, а тяжёлый меч — замедляет.

Бонусы предметов (ассеты в `Assets/LabItems`):

| Предмет | Слот | Эффект |
|---|---|---|
| Стальной меч | Weapon | +12 атака, −0.5 скорость, +5% крит |
| Дубовый щит | Shield | +6 защита, −0.3 скорость |
| Железный шлем | Head | +4 защита, +15 HP |
| Кожаная куртка | Chest | +3 защита, +7% скорость |
| Сапоги скорости | Feet | +1.2 скорость |
| Амулет силы | Amulet | +5 атака, +5% крит |

Панель «Характеристики» показывает итог и зелёным/красным — вклад экипировки.

### 2.5. Управление инвентарём мышью

* Слоты и слоты экипировки реализуют `IBeginDragHandler` / `IDropHandler`
  (uGUI drag & drop). Перетаскиваемый предмет отображается «призраком» под курсором.
* Слот экипировки принимает только предмет своего типа, иначе показывает сообщение.
* Двойной клик по предмету — надеть, по надетому — снять.
* `G` выбрасывает выделенный предмет: он появляется перед игроком, прижат к земле,
  и его можно снова подобрать клавишей `E` — цикл замыкается.

## 3. Практическое занятие №8 — хаотичный ИИ

### 3.1. Идея

Обычная FSM («патруль → погоня → возврат») предсказуема: игрок быстро вычисляет
шаблон. Здесь вместо жёстких переходов используется **взвешенный случайный выбор
действий** с памятью и реакциями на события.

Непредсказуемость достигается четырьмя механизмами:

1. **Взвешенный выбор** из 9 действий, веса зависят от ситуации.
2. **Анти-повтор**: недавние действия штрафуются экспоненциально
   (`antiRepeatStrength`, `historyDepth`) — NPC не зацикливается.
3. **Случайная длительность** каждого действия.
4. **Реакции**: события игры временно смещают веса и с вероятностью
   `reactionChance` мгновенно переключают действие.

### 3.2. Действия

| Действие | Что делает | Зачем игроку «непонятно» |
|---|---|---|
| `Wander` | бродит вокруг точки появления | базовое состояние |
| `Stalk` | крадётся, держит дистанцию, замирает под взглядом | слежка без агрессии |
| `Flee` | убегает | контраст с предыдущим |
| `Ambush` | обходит со спины, ждёт и бросается | атака из неожиданного места |
| `Mimic` | повторяет движение игрока | «он копирует меня» |
| `Taunt` | подбегает, дразнит, убегает | ложная агрессия |
| `FakeGift` | подкидывает предмет-обманку | подбор предмета наказывается |
| `Freeze` | замирает и смотрит | классический «странный NPC» |
| `Blink` | исчезает, пока на него не смотрят | «он был здесь секунду назад» |

### 3.3. Реакции на изменения игрового процесса

`GameEventBus` — статическая шина событий. Её поднимают:
`PlayerInventory` (подбор/экипировка/выброс), `CharacterStats` (здоровье),
`NPCController` (состояние квеста), `ItemPickup` (обманка).

| Сигнал | Реакция (одно из двух, случайно) |
|---|---|
| `PlayerPickedUpItem` | `Stalk` / `FakeGift` |
| `PlayerEquippedItem` | `Flee` / `Ambush` |
| `PlayerDroppedItem` | `FakeGift` / `Taunt` |
| `PlayerDamaged` | `Taunt` / `Ambush` |
| `QuestChanged` | `Taunt` / `Blink` |
| `PlayerLookedAtMe` | `Freeze` / `Flee` |
| `PlayerCameClose` | `Ambush` / `Mimic` |

Кроме событий, NPC сам отслеживает переходы: «игрок посмотрел», «игрок подошёл»,
урон по здоровью (сравнение предыдущего значения), состояние квеста.

`NpcPerception` определяет:
* расстояние и прямую видимость (raycast);
* **смотрит ли игрок на NPC** — угол между `Camera.main.transform.forward`
  и направлением на NPC. Именно это позволяет `Freeze` и «мигание» вести себя
  убедительно.

### 3.4. Архитектура

```
AI/
  ChaosTypes.cs     — ChaosAction, ChaosSignal, ChaosContext, русские названия
  ChaosProfile.cs   — ScriptableObject с настройками хаотичности и репликами
  IChaosActor.cs    — абстракция NPC (позволяет тестировать мозг без сцены)
  IChaosAction.cs   — интерфейс действия (паттерн «Стратегия»)
  ChaosActions.cs   — 9 реализаций действий + фабрика
  ChaosBrain.cs     — взвешенный выбор, анти-повтор, реакции, таблица сигналов
  ChaosAgent.cs     — мост к NavMeshAgent/Animator, телепорт, спавн обманок
  NpcPerception.cs  — зрение и «взгляд игрока»
  ChaoticNPC.cs     — MonoBehaviour-драйвер, подписка на GameEventBus, HUD
```

`ChaosBrain` работает с `IChaosActor`, поэтому его поведение проверяется
юнит-тестами на заглушке — без Unity-сцены и NavMesh.

### 3.5. Наблюдение за NPC

В левом верхнем углу HUD отображается текущее действие, таймер и реплика NPC
(или дистанция до игрока). В консоль выводятся переходы вида:

```
[Chaos] Хаотичный NPC → Засада (t=42.3)
[Chaos] Хаотичный NPC: реакция на PlayerPickedUpItem → Подкидывает обманку
```

## 4. Тесты

### 4.1. Что покрыто

**EditMode** (`Assets/Tests/EditMode`):

* `InventoryModelTests` — добавление, стаки, переполнение, атомарный подбор,
  перемещение/обмен/слияние, экипировка, возврат предыдущего предмета,
  снятие, изъятие, события, вес.
* `StatCalculatorTests` — формула flat/percent, сумма от нескольких предметов,
  защита от отрицательных значений, дельта.
* `ChaosBrainTests` — используются все 9 действий, почти нет повторов,
  нет доминирующего действия, `Mimic` недоступен при стоящем игроке,
  реакция срабатывает при `reactionChance = 1` и не срабатывает при `0`,
  одинаковый seed → одинаковая последовательность, разные seed → разные.

**PlayMode** (`Assets/Tests/PlayMode`):

* подбор предмета и событие `ItemPickedUp`;
* полный инвентарь → предмет остаётся в мире;
* экипировка меняет `Attack` и `MoveSpeed` в `CharacterStats`;
* `PlayerSpeedLink` реально меняет `PhysicsModule.maxSpeed`;
* снятие предмета возвращает его в инвентарь;
* выбрасывание создаёт предмет в мире, и его можно подобрать снова;
* перемещение между слотами;
* хаотичный NPC: мозг создан и работает, реагирует на подбор предмета и на урон.

### 4.2. Запуск

В редакторе: **Window → General → Test Runner → EditMode / PlayMode → Run All**.

Из командной строки:

```powershell
Unity.exe -batchmode -projectPath <проект> `
  -runTests -testPlatform EditMode `
  -testResults <проект>\Logs\editmode-results.xml -logFile -
```

## 5. Пересборка демо-сцены

Меню **Lab 7-8 → 1. Создать демо-сцену** (или `-executeMethod LabGame.EditorTools.LabSetup.BuildDemoScene`).

Скрипт `Assets/Editor/LabSetup.cs`:

1. создаёт ассеты предметов в `Assets/LabItems`;
2. копирует `SampleScene` → `Lab7_8_Demo` (рабочая сцена не изменяется);
3. добавляет игроку `CharacterStats` и `PlayerSpeedLink`;
4. расставляет 9 предметов на земле рядом с игроком (родитель `LabLoot`);
5. создаёт `ChaosNPC` (копия модели NPC без квестовых скриптов) и ставит его на NavMesh;
6. сохраняет сцену и добавляет её в Build Settings.

Проверка: меню **Lab 7-8 → 2. Проверить демо-сцену**.

## 6. Известные ограничения

* Модель NPC взята из ПЗ №6: у аниматора нет триггеров `Taunt`, поэтому
  `ChaosAgent.PlayTrigger` пишет предупреждение в консоль, а не падает.
* Инвентарь создаётся в рантайме (`LabHUD.Ensure`), а не хранится в сцене —
  так он работает в любой сцене и не ломает существующую иерархию.
* Для отключения автосоздания UI (например, в тестах) используется
  `LabServices.AutoCreateInterface = false`.
